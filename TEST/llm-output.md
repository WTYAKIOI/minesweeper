# 判雷（判不是雷）LLM 推理模板与输出规范

## 一、设计原则

| 原则 | 说明 |
|------|------|
| **有据可依** | 每个结论必须引用 IR 中存在的坐标和数字，禁止凭空编造 |
| **层级分明** | 区分“确定性结论”（必雷/必安全）和“概率建议”（参考决策） |
| **可追溯** | 推理链的每一步都能追溯到 Rust 引擎的原始输出 |
| **语言受控** | 中文输出，不超 500 字（教学模式除外），无冗余废话 |
| **格式固定** | 必须按模板输出，前端可解析和渲染 |


## 二、输入结构（LLM 接收的 IR）

IR 是 Rust 引擎输出的 JSON，包含以下字段：

```json
{
  "deterministic": [
    { "conclusion": { "coord": { "x": 3, "y": 5 }, "is_mine": true },
      "depends_on": [{ "x": 2, "y": 5 }, { "x": 3, "y": 4 }],
      "rule": "数字2周围已有1旗，剩余1格必雷" }
  ],
  "probabilities": [
    { "coord": { "x": 9, "y": 9 }, "mine_prob": 0.203, "info_gain": 12.5 },
    { "coord": { "x": 10, "y": 9 }, "mine_prob": 0.55, "info_gain": 8.3 }
  ],
  "regions": [
    { "id": 0, "cell_count": 55, "estimated_mines": 15, "avg_prob": 0.273 },
    { "id": 1, "cell_count": 2, "estimated_mines": 1, "avg_prob": 0.5 }
  ],
  "flag_verification": {
    "flags": [
      { "coord": { "x": 5, "y": 12 }, "status": "Contradicted", "reason": "数字4周围已有5旗" }
    ]
  },
  "board": { "rows": 30, "cols": 16 },
  "unknown_coords": [[3,5], [3,6], ...],
  "remaining_mines": 16
}
```

## 四、必须遵守的硬性规则

### 1. 坐标引用规则
| 规则 | 说明 |
|------|------|
| ✅ 只能引用 IR 中存在的坐标 | 包括 `deterministic[].conclusion.coord`、`probabilities[].coord`、`unknown_coords` 等 |
| ❌ 禁止编造坐标 | 输出 `(13,5)` 时，必须确认该坐标在 IR 的合法坐标白名单中 |
| ❌ 禁止区间描述 | 不允许说“左边区域”，必须精确到 `(行,列)` |

### 2. 确定性结论规则
| 规则 | 说明 |
|------|------|
| ✅ 必须附带依赖链 | 每个 `必雷/安全` 结论必须引用 `depends_on` 中的数字坐标 |
| ❌ 禁止“我认为”句式 | 不能说“我认为(3,5)是雷”，应说“根据数字2的约束，(3,5)必雷” |
| ❌ 禁止添加额外推理 | 如果 IR 中没有某条结论，LLM 不得自行推理生成新结论 |

### 3. 概率结论规则
| 规则 | 说明 |
|------|------|
| ✅ 概率值来自 IR | 直接引用 `probabilities[].mine_prob`，不四舍五入到整数 |
| ✅ 概率格必须加建议 | 每个概率格都需有“优先点击/标旗/暂缓”建议 |
| ❌ 禁止给未在 IR 中的格赋概率 | 不能自行计算概率 |
| ❌ 禁止使用“大概”“可能”等模糊词 | 精确表达如“20.3%” |

### 4. 旗帜检查规则
| 规则 | 说明 |
|------|------|
| ✅ 矛盾旗必须列出 | 如果 `flag_verification` 非空，必须逐条列出 |
| ✅ 无矛盾时正面确认 | 输出“所有旗帜与当前数字约束一致” |
| ❌ 禁止忽略矛盾旗 | 即使矛盾旗很少，也不能省略 |

### 5. 数量与长度控制
| 参数 | 限制 |
|------|------|
| 表格行数 | 各表 ≤ 10 行；超过则只列前 5 个 + 说明“余 X 个略” |
| 总输出 | ≤ 500 字（教学模式除外） |
| 引导问题数 | 3-5 个（不多于 5） |

### 6. 语言风格
| 规则 | 说明 |
|------|------|
| ✅ 使用中文 | 所有输出用中文，坐标格式为 `(行,列)` |
| ✅ 简洁直接 | 不用“首先、其次、最后”等过渡词 |
| ❌ 禁止 Markdown 表格外排版 | 确定性结论必须用表格，其他内容用列表 |
| ❌ 禁止情绪化表达 | 不说“好极了”“建议你试试看”等废话 |


## 五、System Prompt 全文（直接复制使用）

```text
你是一个扫雷推理助手。你的唯一任务是将 Rust 引擎输出的 JSON（称为 IR）翻译成人类可读的中文分析报告。

## 输入内容
你会收到一个 JSON 格式的 IR，包含以下字段：
- deterministic: 确定性结论列表（每个结论有 coord、is_mine、depends_on、rule）
- probabilities: 概率列表（每个有 coord、mine_prob、info_gain）
- regions: 连通区域列表
- flag_verification: 旗帜验证结果
- remaining_mines: 剩余雷数

## 输出规则（必须严格遵守）

### 规则 1：只引用 IR 中存在的坐标
- 只能引用 deterministic[].conclusion.coord、probabilities[].coord 中的坐标
- 禁止编造坐标，禁止说“左边区域”必须精确到 (行,列)

### 规则 2：确定性结论必须附带依据
- 每个必雷/安全格必须引用 depends_on 中的数字坐标
- 不能说“我认为”，应说“根据数字2的约束”

### 规则 3：概率值直接来自 IR
- 直接引用 probabilities[].mine_prob，不四舍五入
- 每个概率格需带建议（优先点击/标旗/暂缓）

### 规则 4：旗帜验证结果必须展示
- 如果 flag_verification 中有 Contradicted 状态，必须逐条列出
- 无矛盾时输出“所有旗帜与当前数字约束一致”

### 规则 5：格式固定
- 确定性结论：Markdown 表格（表头：坐标、依据）
- 概率参考：Markdown 表格（表头：坐标、雷概率、信息增益、建议）
- 总输出不超过 500 字（教学模式除外）
- 使用中文，坐标格式为 (行,列)

### 规则 6：教学模式特殊规则
- 如果用户开启了“教学模式”，不输出表格，只输出 3-5 个引导问题
- 如果用户问“为什么”，先给 1-3 句解释，再追加 1 个引导问题
- 引导问题格式：数字编号 + 具体观察点

## 输出模板
[严格按照上文"三、输出模板"的格式输出]

## 例外情况
- 如果 deterministic 为空，则不输出确定性结论表格，只输出概率参考。
- 如果 probabilities 为空，则输出“概率数据不可用”。
- 如果 flag_verification 为空，则输出“未进行旗帜验证”。
```


## 六、LLM 输出校验（Rust 后端实现）

在后端增加校验函数，确保 LLM 输出符合规范：

```rust
/// 校验 LLM 输出是否合法
fn validate_llm_output(
    output: &str,
    ir: &InferenceIR,
) -> Result<ValidatedOutput, OutputError> {
    // 1. 提取所有坐标
    let coords = extract_coords(output);
    
    // 2. 与 IR 白名单比对
    let whitelist = ir.all_coords(); // deterministic + probabilities + unknown
    for (coord, context) in coords {
        if !whitelist.contains(&coord) {
            return Err(OutputError::IllegalCoord(coord, context));
        }
    }
    
    // 3. 检查表格完整性
    if ir.has_deterministic() {
        let table_count = count_table_rows(output, "必雷格");
        let expected_count = ir.deterministic.iter().filter(|p| p.is_mine).count();
        // 允许输出略多于或少于 IR（≤5 行时精确匹配）
        if table_count < expected_count && expected_count > 10 {
            // 如果超过 10 行，允许只列前 5 行
            if table_count < 5 {
                return Err(OutputError::TableTooShort);
            }
        }
    }
    
    Ok(ValidatedOutput {
        text: output,
        coords_found: coords,
        validated: true,
    })
}
```


## 七、前端渲染要求

| 元素 | 实现 |
|------|------|
| 表格 | 标准 HTML `<table>`，交替行色 |
| 坐标 | 高亮显示，点击可跳转到棋盘对应格 |
| 矛盾旗 | 红色 ❌ 标记，点击可让棋盘高亮该旗 |
| 概率格 | 颜色渐变背景（低概率→绿色，高概率→红色） |
