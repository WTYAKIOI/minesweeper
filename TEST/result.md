# 扫雷棋盘识别测试报告 (result.md)

## 1. ERR.md 问题分析

`ERR.md` 描述了两个主要问题：

### 问题一：前端 OCR 地址错误
- **现象**：前端代码直接使用 Docker 容器内部主机名 `ocr:5001`，浏览器无法解析。
- **根因**：前端 JS 运行在浏览器（宿主机），`ocr` 是 Docker 内部别名。
- **解决方案**：当前 `static/index.html` 已使用相对路径 `/api/ocr`（通过后端代理），符合推荐方案。

### 问题二：Rust 版本不兼容
- **现象**：依赖包需要 Rust 1.88+，但 Dockerfile 使用 `rust:1.82-slim`。
- **解决方案**：将 Dockerfile 改为 `FROM rust:latest AS builder`。

## 2. OCR 测试：1.png → 标准棋盘

### 2.1 原始 OCR 问题

原始 `ocr/app.py` 存在以下问题：

| 环节 | 状态 | 说明 |
|------|------|------|
| 棋盘检测 | ❌ 失败 | `detect_board()` 找不到棋盘轮廓，返回整图 |
| 网格检测 | ❌ 部分 | 垂直线检测失败，靠宽高比猜测尺寸 |
| 旗帜识别 | ⚠️ 部分 | 与数字 3 混淆（同为红色） |
| 数字识别 | ❌ 失败 | Tesseract 未安装，回退几乎全返回 0 |

### 2.2 `ocr/app.py` 代码修改

对 `ocr/app.py` 做了以下改进：

#### `detect_board()` — 增加彩色像素包围盒回退
当轮廓检测失败时，用彩色（非灰色）像素的包围盒定位棋盘区域。

#### `detect_grid_lines()` — 增加自相关分析 + 标准尺寸匹配
- 策略一：形态学线检测（原有）
- 策略二：行列投影自相关分析
- 策略三：标准棋盘尺寸匹配（9×9, 16×16, 30×16）

#### `classify_cell()` — 重写为颜色分析
- 用灰度 mode 区分未翻开（<175）和已翻开空格（>175）
- 用彩色像素平均 BGR 识别数字 1-8
- 旗帜 vs 数字 3：未翻开背景→旗帜，已翻开背景→数字 3

#### `_color_to_number()` — 新增
根据彩色像素平均 BGR 值匹配数字：

| 数字 | BGR 颜色 | 检测条件 |
|------|----------|----------|
| 1 | 蓝 | B>120, R<100, G<100 |
| 2 | 绿 | G∈[80,200), R<100, B<100 |
| 3 | 红 | R>150, B<100, G<100 |
| 4 | 深蓝 | B∈[80,180), R<50, G<50 |
| 5 | 暗红 | R∈[80,180), B<50, G<50 |
| 6 | 青 | B∈[80,180), G∈[80,180), R<50 |
| 7 | 黑 | R<50, G<50, B<50 |
| 8 | 灰 | B/G/R∈[100,170) |

#### `_find_best_offset()` — 新增
在整图上搜索最佳网格偏移，最大化彩色像素密度。

#### `recognize_board()` — 重写
1. 尝试标准棋盘尺寸 (9×9, 16×16, 30×16) 和一系列单元格大小
2. 对每种组合搜索最佳偏移
3. 选取得分最高者进行单元格分类

### 3.4 已知限制

1. **非经典配色**：当前颜色映射基于经典 Windows 扫雷配色，其他主题（浅色/暗色/自定义）的数字颜色不同，导致误识别
2. **无彩色图片**：如7.webp全灰度图片无法识别数字
3. **小尺寸图片**：如8.webp（474×216）只能匹配9×9棋盘
4. **Tesseract 依赖**：颜色识别失败时回退到Tesseract，但环境中未安装

### 3.5 改进方向

1. **自适应颜色方案**：自动检测图片的主色调，动态调整数字颜色映射阈值
2. **棋盘边框检测**：用线检测或边缘检测精确定位棋盘区域
3. **模板匹配**：预先制作各主题的数字模板，用模板匹配代替颜色匹配
4. **安装Tesseract**：在Docker中安装Tesseract作为颜色识别的补充

## 4. AGENT4.md 改进方案实施

按照 `AGENT4.md` 的三阶段改进方案，完成以下全部改进：

### 4.1 阶段一：自适应颜色匹配（P1）

#### 新增函数

| 函数 | 说明 |
|------|------|
| `extract_dominant_colors()` | K-means 聚类提取图片主导颜色，按亮度排序 |
| `adaptive_color_match()` | 对彩色像素做 K-means 聚类，取最大聚类中心匹配已知数字颜色 |
| `normalize_illumination()` | YUV 亮度通道直方图均衡化，解决偏暗/偏亮图片 |

#### 集成方式
- `recognize_board()` 中对偏暗（<80）或偏亮（>220）的图片应用光照归一化
- `classify_cell()` 中经典颜色匹配失败时，触发 `adaptive_color_match()`

### 4.2 阶段二：模板匹配多主题支持（P2）

#### 新增函数

| 函数 | 说明 |
|------|------|
| `detect_theme()` | 根据单元格平均亮度判断主题：classic(>200) / dark(<50) / flat |
| `template_match_digit()` | 从 `templates/{theme}/` 和 `templates/learned/` 加载模板，用 `cv2.matchTemplate` 匹配，置信度阈值 0.7 |

#### 模板库结构
```
ocr/templates/
├── classic/    # 经典主题模板
├── dark/       # 暗色主题模板
├── flat/       # 扁平化主题模板
├── flags/      # 旗帜模板
└── learned/    # 用户反馈学习的模板
```

### 4.3 阶段三：Tesseract 环境安装 + 集成（P0/P3）

#### Dockerfile 更新 (`ocr/Dockerfile`)
```dockerfile
RUN apt-get install -y --no-install-recommends \
    tesseract-ocr \
    tesseract-ocr-eng \
    libtesseract-dev \
    libleptonica-dev \
    ...
ENV TESSDATA_PREFIX=/usr/share/tesseract-ocr/5/tessdata
COPY templates/ ./templates/
```

#### requirements.txt 更新
新增 `scikit-learn>=1.3` 依赖

#### 三层回退链 `ocr_with_fallback()`
```
输入单元格 → 自适应颜色匹配 (K-means)
                ↓ 失败/低置信度
             模板匹配 (多主题)
                ↓ 失败/置信度<0.7
             Tesseract OCR (二值化+放大)
                ↓
             输出 (数字, 方法, 置信度)
```

### 4.4 阶段四：用户反馈学习机制（P4）

#### `auto_learn_template()`
- 接收确认的单元格图片和数字
- 裁剪数字区域，保存到 `templates/learned/digit_{N}_{timestamp}.png`
- 后续模板匹配时自动加载 learned 目录

#### 新增 `/api/learn` 路由
```json
POST /api/learn
{
  "image": "base64编码的单元格图片",
  "digit": 3,
  "theme": "learned"  // 可选
}
→ {"success": true, "template_path": "templates/learned/digit_3_xxx.png"}
```
